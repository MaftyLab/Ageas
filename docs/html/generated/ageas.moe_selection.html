ageas.moe_selection

ageas.moe_selection(hangar: Hangar, query_dataset=None, cache_dir: str = None, accelerator: str = 'cpu', cuda_devices: list = None, using_model_types: list = None, using_model_list: list = None, kfold: int = 5, valid_fraction: float = 0.1, stratified_kfold_test: bool = False, stratified_kfold_valid: bool = False, n_dataloader_workers: int = 0, mass_ladder: list = None, floor: int = 20, relative_delta: float = 0.1, ladder_choice: str = 'sparsest', exp_sample_limit: int = 200, explain_args: dict = None, min_relative_gain: float = 0.01, max_steps: int = 50, competence_tolerance: float = 0.02, refit: str = 'competent', cell_weights=None, extend=None, seed: int = 42) → MoE_Deck

Route every unit to its key features and integrate the ones that help each other.

Parameters:

  • hangar – Source hangar from which the candidate units are taken.

  • query_dataset – Labelled terminal cells (AnnData-backed corpus).

  • cache_dir – Folder for Lightning logs. None uses a fresh temporary folder; never point it inside Dropbox.

  • accelerator – 'cpu' or 'cuda'.

  • cuda_devices – GPU indices; None uses every visible GPU.

  • using_model_types – Whitelist of model types from the hangar.

  • using_model_list – Whitelist of unit IDs from the hangar.

  • kfold – Number of folds.

  • valid_fraction – Fraction of each fold’s training part that judges the pruning ladder. Must be positive.

  • stratified_kfold_test – If True, use class-stratified folds.

  • stratified_kfold_valid – If True, stratify the validation split.

  • n_dataloader_workers – Dataloader workers for units whose config does not set dataloader_workers.

  • mass_ladder – Attribution-mass levels from weakest to strongest pruning. Defaults to [0.95, 0.8, 0.6, 0.4]; an empty list turns routing off (every unit keeps all features).

  • floor – Minimum number of positively attributed features kept per class.

  • relative_delta – Largest validation log-loss increase accepted for a narrower version of a unit, as a fraction of the all-feature version’s loss.

  • ladder_choice – 'sparsest' keeps the strongest level within relative_delta; 'best' keeps the version with the lowest validation loss the search reached, all features included (see search_ladder()).

  • exp_sample_limit – Cells per class explained by Integrated Gradients when ranking a neural network’s features.

  • explain_args – Extra keyword arguments for the attribution step (e.g. {'exp_step': 50}).

  • min_relative_gain – Smallest OOF log-loss improvement a unit must bring to be integrated, and to stay integrated, as a fraction of the ensemble’s current loss.

  • max_steps – Largest number of additions in the no-harm selection.

  • competence_tolerance – Units whose out-of-fold balanced accuracy is within this of the best unit’s are competent: candidates for the committee (select_committee()). They are refitted like the integrated units.

  • refit – 'competent' refits the integrated and competent units; 'all' refits every routed unit, so any committee can be drawn from the run’s predictions afterwards.

  • cell_weights – Weight of every terminal cell in each validation log-loss, for routing and integration alike, e.g. the shift-aware weights of shift_weights(). None (ordinary validation) counts every cell alike.

  • extend – Optional second round. Called once with unit_id -> out-of-fold log-loss (under cell_weights) of the first round’s units, it returns unit_id -> Unit to add; those are routed in the same folds and compete with the rest for integration.

  • seed – Seed for the fold split and for every fit.

Returns:

The MoE_Deck of the run.
