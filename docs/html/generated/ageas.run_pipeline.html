ageas.run_pipeline

ageas.run_pipeline(terminal_dataset, query_x, workdir: str, selection: dict = None, routing: dict = None, synergy: dict = None, committee: dict = None, validation: str = 'shift', refine: bool = True, rules: bool = True, accelerator: str = 'cpu', cuda_devices: list = None, unit_types: list = None, seed: int = 0, graph: dict = None, graph_settings: dict = None) → PipelineResult

Run Ageas v2 on one dataset.

Parameters:

  • terminal_dataset – Labelled terminal cells (AnnData-backed corpus, as moe_selection() takes it).

  • query_x – Progenitor cells’ model input, (n_cells, ..., n_features) in the terminal cells’ feature order. No labels.

  • workdir – Folder for the generated panel (panel/) and the Lightning logs (cache/); never inside Dropbox.

  • selection – Fold settings for moe_selection() (kfold, valid_fraction, …).

  • routing – Routing settings (mass_ladder, floor, …).

  • synergy – Integration settings (min_relative_gain, …).

  • committee – Committee settings: tolerance (competence, see competent_units()), max_jsd and min_majority (see select_committee()), rule ('mean' or 'logit', see vote()), balance ('unit': every member one vote; 'type': every model type one vote), with_mixture (if True, the no-harm mixture counts as much as the whole committee in the vote) and refit ('competent' or 'all', see moe_selection()).

  • validation – 'shift' steers routing and integration by the shift-aware weights; 'ordinary' counts every terminal cell alike. The strategy check reports both either way.

  • refine – If True, a second round adds one unit past the edge of every family whose best-validated unit sits at that edge (extend_panel()).

  • rules – If False, the profile’s rules do not shape the panel (design_panel() with use_rules=False).

  • accelerator – 'cpu' or 'cuda'.

  • cuda_devices – GPU indices.

  • unit_types – Keep only these unit types of the designed panel (for quick checks; benchmark runs use the whole panel).

  • seed – Seed for the profile, the weights, the folds and every fit.

  • graph – Every cell for the graph stage, one preprocessing for all: features (terminal, query and unlabeled cells), labels (terminal class index; -1 for query and unlabeled cells), query_index (each query cell’s row, in query_x order) and kind ('pca' or 'lsi', see embed()). None: no stage, and the vote is the output.

  • graph_settings – The stage’s settings (protocol graph, see graph_stage()).
